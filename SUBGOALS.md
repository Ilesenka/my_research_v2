# Дерево под-целей: проверка надёжности верификатора EXFOR

**Корень (что проверяем целиком):** Верификатор базы данных EXFOR корректно проверяет перенос числовых значений и единиц из исходных записей (для поддерживаемых форматов), отбор измерений по Z и энергии, сохранение верхних пределов и соответствие очереди проверки основной таблице.

**Постановку проверил автор:** Да. Сверено: безразмерность IR; перевод энергии в МэВ; отбор по Z продукта; включённые границы $Z = 60-80$ и $E^m = 10-60$ МэВ; различие нуля и пропуска; обработка неизвестной энергии и верхних пределов и пустых наборов.

## Дополнительные пояснения

1. **Объект проверки:**

Существующий скрипт `verify_exfor.py`. Проверяем его на контролируемых примерах таблиц и соответствующих исходных записей EXFOR.

2. **Существенные условия:**

- $E^m$ имеет смысл, установленный правилами проекта (как для обычного тормозного облучения): энергия электронного пучка, она же верхняя граница тормозного спектра.
- Эквивалентные записи энергии должны давать одинаковый результат: 20 МэВ = 20000 кэВ.
- IR безразмерно; исходные 25 процентов соответствуют 0.25.
- Для обычной записи без документированного исправления значение в таблице должно соответствовать исходнику с учётом установленного численного допуска.

3. **Крайние случаи:**

- Границы диапазонов включены: $60 ≤ Z ≤ 80$; $10 ≤ E^m ≤ 60$ МэВ.
- При подходящем Z и неизвестной энергии $E^m$ статус отбора — `pending`. Если один из фильтров (по Z или по $E^m$) достоверно не пройден — `excluded`.
- Исходное `IR ≤ 0.001` не превращается в точечное измерение `IR = 0.001`.
- Пустая основная таблица при наличии ожидаемых точек в исходниках должна вызывать ошибку.
