# ATTEMPTS.md — журнал попыток проверок (неделя 7)

Файл фиксирует только фактически выполненные попытки: команду, вывод, код
завершения и заключение. Прошлые попытки не восстанавливаются догадками.
Подробности по подцелям — в `results/artefact7/`.

## Правило трёх попыток

Действует для всех подцелей G0–G8.

1. На одну проверку — не более трёх попыток исправления.
2. Попыткой считается запуск проверки после изменения кода или данных.
   Ошибки построения собственного стенда (опечатки в схеме строки, забытые
   ключи) попытками проверки не считаются, но фиксируются отдельно.
3. После третьей неудачи по одной и той же причине работа останавливается:
   план пересматривается, задача помечается как заблокированная, в отчёте
   указывается причина и необходимое решение. Четвёртая попытка «наугад»
   не выполняется.
4. Две неудачи подряд по одной причине — сигнал пересмотреть план, не
   дожидаясь третьей (согласовано с `AGENTS.md`, раздел 7).

Состояние правила: **не активировано**. В сессии G1 хватило одной попытки.
