2. ЧТО ИМЕННО ПРОВЕРЯЕТ ТЕСТ (чтение кода, не запуск)
================================================================
test_numeric_copy (строки 200-219) вызывает assert_numeric_copy(verifier, n, unit):
  - строит синтетическую точку: исходная ячейка DATA = n с единицей unit,
    табличное ir_value_numeric = n/1000 (для PER-CENT) или n (для NO-DIM);
  - утверждает отсутствие любых ERROR;
  - сдвигает табличное значение на +1e-16 и требует отсутствия ERROR;
  - сдвигает на +0.01 и требует ERROR с кодом NUMERIC_SOURCE;
  - проверяет decimal("0") == 0 и decimal("") is None.
Генератор: n ∈ [0, 10^6], unit ∈ {NO-DIM, PER-CENT}, плюс примеры
(n=0, NO-DIM) и (n=25000, PER-CENT); max_examples=60, derandomize=True.

Проверяемый код верификатора (verify_exfor.py):
  - строки 602-603: normalized = raw * 0.01 только для unit == 'PER-CENT',
    и только если unit ∈ {'NO-DIM', 'PER-CENT'};
  - строка 611: if target is not None and not close(target, preferred):
    report.add('ERROR', 'NUMERIC_SOURCE', rid);
  - строки 51-54: close(a, b) = |a-b| <= max(1e-14, |b|*1e-10);
  - строки 555-559: отдельная проверка SOURCE_SCALAR — текстовая копия
    исходной ячейки и её единицы в ir_value_raw.

5. ОЦЕНКА СООТВЕТСТВИЯ ТЕСТА УТВЕРЖДЕНИЮ G1
================================================================
Утверждение G1: «IR соответствует исходнику после перевода единиц,
в пределах допуска».

Подтверждено тестом и независимо:
  - перенос числа из исходной ячейки в таблицу (NO-DIM) — да;
  - перевод процентов 25 -> 0.25 и 25000 -> 250 — да, включая границы;
  - отказ при отсутствии перевода и при двойном переводе — да;
  - отказ при расхождении 0.01 и допуск расхождения 1e-16 — да;
  - ноль не путается с пропуском (decimal('0') == 0, decimal('') is None) — да;
  - проверка не тавтологична: подмена исходника табличным значением ловится — да.

Ограничения соответствия (тест слабее утверждения в трёх местах):
  1. Величина допуска не закреплена. Тест проверяет только «1e-16 принято,
     0.01 отвергнуто». При b = 250 это ограничивает относительный допуск
     сверху значением ~4e-5, то есть допуск, ослабленный в 100-1000 раз
     (1e-10 -> 1e-2 или 1e-4), тест проходит. Заявленный в коде допуск
     1e-10 тестом не подтверждается.
  2. Относительный член допуска не проверяется. Смещение 1e-16 меньше
     абсолютного порога 1e-14, поэтому утверждение «1e-16 принято»
     выполняется и при допуске 1e-20, и при чисто абсолютном допуске
     (|b| -> 1). Масштабирование по |b| тестом не затронуто.
  3. Отказ для неподдерживаемой единицы не проверяется. Генератор даёт
     только NO-DIM и PER-CENT, поэтому снятие списка единиц (любая единица
     трактуется как безразмерная) тест не ловит; независимо проверено,
     что верификатор такую единицу отвергает (NUMERIC_SOURCE).

Неточность документации (не влияет на вердикт): docstring теста говорит
«nonnegative IR 0..1000», но при n до 1e6 и PER-CENT IR достигает 10000,
а при NO-DIM — 1e6. Диапазон 0..1000 в верификаторе не проверяется;
это описание генератора, а не проверяемое свойство.
